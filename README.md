# Домашние рецепты

Закрытая семейная книга рецептов с подробными шагами, фотографиями, списком
ингредиентов и фоновой сборкой корзины.

## Возможности

- общая коллекция рецептов для нескольких пользователей;
- обложки блюд и фотографии этапов приготовления;
- пересчёт ингредиентов под нужное число порций;
- основные продукты и отдельная группа приправ и домашних запасов;
- поисковые ссылки и фоновая сборка корзины в поддерживаемых магазинах;
- настраиваемый приоритет магазинов и маркировка сомнительных замен;
- импорт статей и видео в проверяемые черновики;
- пользовательские пожелания к импорту;
- чат с Гермесом в редакторе черновика для переработки готового рецепта обычным
  текстовым пожеланием;
- разделение независимых блюд на отдельные черновики, а компонентов блюда —
  на секции одного рецепта;
- автоматические обложки, фотографии шагов и примерная калорийность;
- фильтр по автору, мгновенный нечёткий поиск и экран фоновых задач;
- закрытая регистрация: первого владельца создают при первоначальной настройке,
  остальных пользователей добавляет администратор;
- тёмная тема по умолчанию с переключателем на светлую и локальными шрифтами
  без внешних CDN;
- PostgreSQL, Docker health checks и постоянное хранение изображений.

## Запуск и проверка

Скопируйте `.env.example` в `.env`, задайте секреты и параметры своего
окружения, затем запустите приложение:

```bash
cp .env.example .env
docker compose up --build
```

Адрес и порт определяются локальной конфигурацией. При первом открытии
создайте владельца. Полная проверка проекта:

```bash
./scripts/check.sh
```

## Импорт рецептов

Страница или субтитры извлекаются без участия модели. До обращения к AI
локальная проверка блокирует материалы не о приготовлении еды и типовые
конструкции prompt injection. Модель получает очищенный текст как недоверенные
данные без доступа к инструментам и возвращает один или несколько
структурированных рецептов.

Самостоятельные блюда становятся отдельными черновиками, а соусы, гарниры и
другие дополняющие компоненты — секциями одного рецепта. Вода исключается из
ингредиентов. Из источника по возможности загружаются обложка и фотографии
шагов. Для страниц с корректной Schema.org `Recipe`-разметкой доступен
детерминированный импорт без AI. Для видео необходимы доступные субтитры.

Можно подключить доверенный OpenAI-совместимый провайдер. Его endpoint, модель,
ключ и таймаут задаются переменными `RECIPE_AI_*` в runtime-окружении. Скрипт
`scripts/connect-hermes-pi.sh` настраивает изолированный профиль без toolsets;
конкретные адреса и учётные данные передаются через окружение и не должны
храниться в репозитории.

В редакторе любого черновика доступен чат с Гермесом. Каждое пожелание попадает
в ту же фоновую очередь, но перерабатывает только выбранный рецепт на основе его
текущей сохранённой версии. Если рецепт изменили или опубликовали, пока Гермес
работал, результат не записывается поверх более свежих правок.

## Сборка корзины

Корзина собирается отдельным изолированным browser-профилем. Агент ищет товары,
рассчитывает число упаковок и добавляет их, но не переходит к оформлению и не
подтверждает заказ или оплату. Поиск и изменение общей серверной корзины
выполняются последовательно: параллельные browser-сессии не используются, пока
инструменты не обеспечивают технически ограниченный read-only поиск.

Если значительная часть списка недоступна, изменения откатываются. Готовая
корзина ждёт подтверждения ограниченное время, после чего worker удаляет только
товары текущей попытки. Содержимое, добавленное ранее, не уменьшается.

Профиль автоматизации настраивается скриптом
`scripts/connect-hermes-cart-pi.sh`. Для ручной авторизации отдельного
пользователя запустите `scripts/cart-browser-login-pi.sh` и следуйте его
подсказкам. Адреса automation-сервисов, SSH targets и состояние браузера должны
оставаться только в локальной конфигурации.

## Оформление

Все цвета живут в CSS-переменных `recipes/static/recipes/app.css`: блок `:root`
описывает тёмную тему (она по умолчанию), блок `[data-theme="light"]` — светлую.
Новые стили берут цвета только из переменных, иначе элемент сломается в одной из
тем.

Выбранная тема хранится в `localStorage` под ключом `theme`. Переключатель — в
шапке, а начальное значение `data-theme` выставляет инлайн-скрипт в `base.html`
до первой отрисовки, чтобы тёмная тема не моргала светлой.

Шрифты — Inter (интерфейс) и Literata (заголовки), лежат в
`recipes/static/recipes/fonts/` как переменные woff2 и подключены через
`@font-face`. Запросов к внешним CDN нет. Начертания задаются переменными
`--font-sans` и `--font-display`.

Иконки вкладки и приложения собираются из `recipes/static/recipes/icon.svg`:

```bash
cd recipes/static/recipes
rsvg-convert -w 512 -h 512 icon.svg -o icon-512.png
rsvg-convert -w 192 -h 192 icon.svg -o icon-192.png
rsvg-convert -w 180 -h 180 icon.svg -o apple-touch-icon.png
for size in 16 32 48; do rsvg-convert -w $size -h $size icon.svg -o /tmp/icon-$size.png; done
magick /tmp/icon-16.png /tmp/icon-32.png /tmp/icon-48.png favicon.ico
```

## Деплой и резервное копирование

Workflow `.github/workflows/deploy.yml` проверяет pull request, а после merge в
`main` публикует неизменяемый образ и обновляет приложение через self-hosted
runner. SSH target, корень приложения, bind address и health endpoint задаются
в закрытой конфигурации репозитория; runtime-секреты хранятся только на целевом
сервере.

Скрипты в `scripts/deploy/` выполняют обновление и проверку состояния, не
передавая постоянные секреты в GitHub. Локальные параметры инфраструктуры не
документируются в репозитории и должны поступать через переменные окружения или
закрытую конфигурацию runner.

Для резервного копирования используйте `scripts/backup-truenas.sh`. Резервная
копия должна включать дамп PostgreSQL, пользовательские изображения и закрытый
runtime-файл окружения. Храните копию на отдельном носителе и никогда не
публикуйте runtime-секреты.
